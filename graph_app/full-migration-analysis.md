## 1. Manager snapshot

graph_app is the IntRisk GRC (SOX) **browser UI**. Users do not open it as
its own website. **WDesk** loads the Dart package `w_sox`. Production is
already a mix of Dart-compiled JS plus extra JS (`graph_app_js`,
Highcharts, `w_table` bindings).

**You cannot wait for graph_ui / w_table / Audit TypeScript before starting.**
Those packages have the same Dart-only problem. The safe path is **partial
migration**: some SOX panels in TypeScript, the rest in Dart, two JS
bundles on the same WDesk page.

**Vite is not in graph_app today (Confirmed).** The build story below is
how we would **add** it next to the existing `dart2js` CDN publish.

### Headline inventory (Confirmed, 26 Aug 2026)

| Count | What |
| --- | --- |

| 1,099 | Handwritten by suffix (not `.g.dart` / `.sg.dart`) |

## 2. Vite build and deploy (plain language for managers)

### What exists today (Confirmed)

On every merge to master / tag, [`.github/workflows/ci.yml`](.github/workflows/ci.yml)
already publishes **four artifacts** from **one product**:

1. Dart **pub package** `w_sox` — WDesk depends on this
2. **CDN** JS/CSS from `app/` (`dart2js` via `Workiva/gha-dart/build`)
3. **Docker** WDesk image (`Dockerfile-wdeskapp` copies `cdn_assets.tar.gz`)
4. **FEWS** using [`app/web/manifest.yaml`](app/web/manifest.yaml)
   (`name: w_sox_app`)

The browser already loads **non-Dart JS**. Paths are in
[`lib/src/sox/sox_ui/src/experiences/static_asset_constants.dart`](lib/src/sox/sox_ui/src/experiences/static_asset_constants.dart):

- `packages/graph_app_js/staticAssets/js/commonApp.bundle.js`
- `packages/w_table/wtableBindings.js`
- Highcharts, drawing, PDF.js, workflow forms

A TypeScript panel is the same idea: **another JS file on the CDN**.

**There is no `vite.config`, no `package.json` app, and no `.tsx` in
graph_app (Confirmed).** The steps below are **Proposed**, matching how
ts-grc already ships TypeScript (**Prior research**) and how this repo
already loads extra JS (**Confirmed**).

### The picture

```text
Developer merges a PR
        │
        ▼
   GitHub Actions (same pipeline as today)
        │
        ├── dart2js (unchanged)  →  Testing, reports, graph_ui, w_table…
        └── vite build (new)     →  one small SOX TypeScript bundle
        │
        ▼
   Both JS files go into cdn_assets.tar.gz
        │
        ▼
   CDN + Docker + FEWS  (same as today)
        │
        ▼
   User opens GRC in WDesk
        │
        ├── Dart JS runs the experience (route, login, licensing)
        └── When that panel opens, Dart asks the browser to load the
            TypeScript JS (same mechanism as graph_app_js)
```

Users still see **one product**. They do not get two websites. This is
**not** a microservice.

### Step-by-step (POC = Model A)

1. **Keep Dart `w_sox` in WDesk’s pubspec.** Do not delete it.
2. **Add a small TypeScript folder** in graph_app (for example `ts/`)
   with Vite + React + `@workiva/unify` (**Prior research:** same stack
   as ts-grc).
3. **CI:** after the existing `gha-dart/build` of `app/`, run
   `vite build`. Copy `dist/*.js` into the CDN tarball next to the
   dart2js output (**Proposed**; needs a one-line job in `ci.yml`).
4. **Dart experience** that owns the panel calls
   `loadStaticAssets` with the new JS path — same pattern as
   `StaticAssets.js.graphAppJsCommonApp` (**Confirmed** pattern;
   **Proposed** for the new file).
5. **WDesk** does not change. Rollback = previous `w_sox` + CDN tag.

### Later (Model B — microfrontend)

When the panel is a real GRC experience, publish the Vite output as
its **own** FEWS/CDN artifact (ts-grc style). WDesk **loads two
frontends**: Dart `w_sox` + SOX TypeScript MFE. Still one product.
Independent rollback of the TypeScript screen.

### What Vite does *not* do

- It does not compile `.dart` files
- It does not let TypeScript `import` `graph_ui` or `w_table`
- It does not replace Frugal/NATS
- It does not require a new Kubernetes service

**POC success:** one Unify panel on staging WDesk, Dart Testing
unchanged, rollback by CDN tag.

## 3. What graph_app is (architecture, with paths)

### 3.1 Product and entry

| Item | Detail | Evidence |
| --- | --- | --- |
| Package | `w_sox` 10.4.54 | `pubspec.yaml` |
| Nested app | `app/` = `w_sox_app` (local / FEWS) | `app/pubspec.yaml`, 7 Dart files outside build |
| Public entry | Experience configs + landing widgets | `lib/experience_configs.dart`, `lib/landing_page_widgets.dart` |
| FEWS registry | Registers SOX, Audit, viewer, landing | `app/lib/src/graph_experience_registry.dart` |
| Runtime module | `GraphModule` — NATS, graph client, SoxStore | `lib/src/_shared/graph_module.dart` |

**Confirmed:** production is not a standalone SPA. WDesk `pub`-depends
on `w_sox`.

### 3.2 UI

**Current (Confirmed):** OverReact (`over_react` in 429 `lib/` files),
Unify Dart (`unify_ui` in 209 files), legacy skin (`web_skin_dart` in
303 files). ~70 SCSS files under `lib/`.

**TypeScript (Prior research):** rewrite to React 18 + `@workiva/unify`.
No OverReact→TS converter.

**Shared Dart widgets this repo does not own** (cannot `import` from
TS): `graph_ui`, `w_table`, `audit`, comments, attachments, outline,
viewer, drawing, dashboard, spreadsheet. Asset paths:
`lib/src/sox/sox_ui/src/experiences/static_asset_constants.dart`.

### 3.3 State management

**Confirmed:** **both** Flux and Redux.

- Flux: `GraphModule` / `SoxStore` / `SoxActions`
  (`lib/src/_shared/graph_module.dart`,
  `lib/src/_shared/flux/sox_store.dart`). ~14 Flux-related files.
- Redux: newer slices (data list, reports, bulk import, upgrade
  wizard). ~104 Redux-related files under `lib/`.

Dart and TypeScript **cannot share one store**. Hybrid: TypeScript is
presentational (props/JSON). Whole TS experience: Redux Toolkit local
to that screen (**Prior research:** ts-grc).

### 3.4 Caching

**Confirmed:** in-memory **stash** caches for test-form list, titles,
controls — `lib/src/sox/sox_ui/src/sox_caching.dart`. Decorators:
`lib/src/sox/services/test_form_repository_cache_decorator.dart`,
`test_step_repository_cache_decorator.dart`. Workspace context cache
used by access checks:
`lib/src/_shared/access/workspace_context_cache.dart`.

TypeScript replacement: RTK Query / Apollo cache per experience
(**Prior research**). Do not share the Dart stash instance.

### 3.5 APIs

**Confirmed in `GraphModule` and services:**

| Channel | Used for | Paths |
| --- | --- | --- |
| Frugal + NATS | Live graph, GRC testing, form-export status | `graph_module.dart` (`messaging.FrugalMessagingProvider`, `w_graph_client`) |
| HTTP Frugal | Some jobs (`useHttp: true` pattern elsewhere) | Open to catalog per call |
| REST / HTTP | Graph bridge import/export, identity | `lib/src/_shared/http_graph_api.dart` (`graph-api-bridge`, `identity`) |
| OpenAPI / Dio | Upgrade / Phoenix migration | `lib/src/upgrade_api/` |

**Org position (Prior research):** Frugal is **not supported in
TypeScript**. ts-grc uses Apollo GraphQL + RTK Query REST.

**Open:** which SOX NATS subjects already have GraphQL/REST on
evergreen/graph.

### 3.6 Authentication and access

**Confirmed:** no login UI in this repo. Shell session via
`w_session` / `AppContext`. Gate:
`canUserAccessV2` in `lib/src/_shared/access/access.dart` (licensing
abilities + workspace `contextKindIds`, PBC suppression). SOX
abilities: `lib/src/sox/sox_access.dart`, `sox_abilities.dart`.
OAuth scopes live on experience configs (`sox|r/w`, `scim|r`,
`linking|*`, etc.).

TypeScript must **not** grow a login page. Use
`@workiva/session_mfe_service` (**Prior research**). Copy the same
scope strings onto any MFE manifest.

### 3.7 Routing

**Confirmed:** WDesk experience `routeSegment` on each
`*ExperienceConfig` (30 files). Deep-link helpers
`GraphRoutePaths` come from **graph_ui**, not this repo (e.g.
`lib/src/data_experience/focus_list/experience_configs/data_types_experience_config.dart`).

TypeScript: keep the same URI segments. React Router only **inside** a
screen. Do not change deep links.

## 7. Recommended step-by-step plan

Do **not** migrate graph_ui first. Do **not** split SOX into
microservices.

### Phase 0 — decisions (1–2 weeks)

1. Approve **POC, not rewrite**.
2. Pick house: **Model A** (Vite JS on existing CDN) vs **Model B**
   (ts-grc MFE). Recommend A for POC.
3. Confirm Frugal stays Dart; TS uses GraphQL/REST only.
4. Name a backend owner for SOX GraphQL/REST coverage.

### Phase 1 — POC-1 hybrid load (2–4 weeks)

5. Add `ts/` + Vite; **do not** remove dart2js.
6. One Unify panel with **no** graph_ui, **no** w_table, **no** NATS
   (Support pruning tab, a landing chrome widget, or upgrade-wizard
   step). Paths in §4.
7. Dart `loadStaticAssets` loads the Vite JS (copy
   `static_asset_constants.dart` pattern).
8. Prove: same route, same `canUserAccessV2`, one LD flag, error
   boundary, `make serve` still works.
9. One Vitest/RTL test. Dart unit host still mounts.

### Phase 2 — POC-2 one API (after POC-1)

10. Call **one** REST or GraphQL endpoint with the WDesk session
    (upgrade API is the most realistic **Confirmed** REST in-repo:
    `lib/src/upgrade_api/`).
11. If no GraphQL for SOX: stop. Do not invent browser NATS.

### Phase 3 — first-wave panels (quarters, not a big-bang)

12. Upgrade wizard (closed REST cluster).
13. Support tabs that are Unify-only; leave Support **shell**
    (`support_view.dart` uses graph_ui `ContentFrame`) in Dart.
14. Landing-widget chrome (key resources views are closed; recency
    widgets that import audit stay Dart).
15. Export-list **toolbars**; list body stays Dart until graph_ui
    story.
16. Testing **list chrome** (some dialogs are closed); not the test
    form.

### Phase 4 — stay Dart until other teams / APIs exist

17. Test form, smart table, data forms, raw graph, evidence tester,
    planning Gantt, dashboards, attachments/outline/viewer.
18. Analyze **audit** and **graph_ui** as their own repos (living
    analysis table).
19. Replace NATS screens only when GraphQL/REST exists.

### Phase 5 — cut over (years)

20. Optional: promote panels to ts-grc MFEs (Model B).
21. Remove `w_sox` from WDesk **only** when every experience
    (including landing widgets and embeddable spreadsheet) has an MFE
    or an explicit Dart island owned elsewhere.
